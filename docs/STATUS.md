## Decisions

Choices between options, with the reason. Date and name each one.

- _2026-11-22 (vinyx1):_ The phone app signs in as a patient with the code from that patient's Profile & settings (scan the QR code, or type its 6 letters; the `/pair` page opens the app for camera scans). The server swaps the one-use code for a per-phone token and files every upload under that patient, so the hard-coded "Vincent" is gone and anonymous uploads are refused (they used to land in the owner's account, which a public server can't allow). The app goes back to sign-in, saying why, when the token ends (demo over, patient deleted, signed out). Release builds keep ML Kit's classes from R8: shrinking them crashed Scan the code.
- _2026-11-22 (vinyx1):_ One live demo per browser, not per internet address: at the symposium every visitor uses our laptop on one Wi-Fi, so an address rule would allow one demo an hour for the whole table. Requesting again while a demo runs offers "Continue that demo" (claim token in an HttpOnly cookie, hash on the server); End demo frees the browser for the next visitor. A private window gets around it; the per-address cap (20/hour) and 100-live cap still bound abuse. The sign-in page is now only the form, centred.
- _2026-11-22 (vinyx1):_ Patients can be deleted (Profile & settings, after a confirmation naming them and their sessions). The server moves recordings only that account holds to `<account>/deleted/` rather than erasing them, so a mistake can be undone by hand; patients whose sessions are in shared, committed files (`data/sample`) are hidden for that account instead, so deleting never changes the repo. The dashboard also re-reads sessions right after an account change, and works with no patients at all.
- _2026-11-22 (vinyx1):_ Accounts and 1-hour demos. The dashboard now needs a sign-in (`components/SignIn.tsx`); the landing page's buttons say "Try the demo". A small Node server (`software/web/server/`: `api.ts`, `accounts.ts`, `index.ts`) replaces the dev-only Vite add-ons; the same API runs in `npm run dev` and `npm start` (production, for Railway). The owner's account (`node server/set-owner.ts <email>`) sees the repo's `data/`; "Request a 1-hour demo login" makes a temporary account with two example patients that is deleted after the hour, or at once with End demo (for visitors at the table). No database: state is files in `data/state/` (git-ignored), passwords as scrypt hashes, sign-in tokens only as hashes, HttpOnly cookies. Limits because it's public: 100 live demos, 20 per address per hour, 15 new Claude summaries per demo. Add patient works (name only, both kinds of account), and each patient's Profile & settings shows a Connect a phone QR code with a 6-letter code (10 minutes); the phone app scanning it comes next. `export.py --data` and `fake_history.py --out` let the server keep one data folder per account. The dashboard reads `/api/sessions` instead of `public/sessions.json`.

- _2026-11-21 (vinyx1):_ Serial commands `G` (start a session), `X` (end it) and `?` (status, answered by a new `I` line), so a phone app on the same USB cable can run a session without the START button. START still works as before. `G` and `X` set a one-shot flag the state machine reads like a START press, so calibration, blocks and the end of a session are unchanged. `protocol.py` parses `I` (`Status`), `logger.py --start` sends `G`. Old firmware answers the new commands with `E,unknown command`. Compiled for the R4 Minima; not yet tested on the device. Branch `phone-app`, toward an Android app (Samsung S22 over USB-C OTG).
